# E2E-тесты

Навык отвечает на вопрос «**как тестировщику проверить проект целиком**».
Unit — `skills/testing`; интеграционные — `skills/integration-testing`.

## Кто и что

- **Владелец — тестировщик.** Он пишет сценарии, ведёт тестовые данные и
  отвечает за приёмку. Разработчик обеспечивает стенд, доступы, сброс данных
  и чинит найденные дефекты.
- Только критические пользовательские сценарии: создать заказ, оплатить,
  получить отказ. Не весь функционал.
- Один тест — один сценарий. Детальные проверки остаются в unit и
  интеграционных тестах.
- E2E не заменяет нижние уровни и не должен быть единственным доказательством
  работы фичи. Если сценарий проверяется unit или integration — проверять там.

## Где и как

- Живут в `tests/e2e/`, отдельный тег:

```go
//go:build e2e

package e2e_test
```

- Запуск: `go test -tags=e2e -count=1 ./tests/e2e/...`.
- Цель в `Makefile`:

```make
test-e2e:
	go test -tags=e2e -count=1 ./tests/e2e/...
```

- Поднимается всё приложение и реальные зависимости тестового стенда.
- Внешние системы — только тестовые; production, платные API и реальные
  секреты запрещены.

## Стабильность

- Уникальные идентификаторы и изолированные данные на каждый прогон.
- Очистка в `t.Cleanup`; повторный запуск не зависит от предыдущего.
- На всё внешнее — `context.WithTimeout`; `time.Sleep` для синхронизации
  запрещён. Нужно ожидание — polling с дедлайном.
- Проверяется пользовательский результат: код ответа, состояние через API,
  видимый результат. Не внутренние логи и не таблицы БД, если есть API.
- При падении сохраняются логи приложения, ответы и артефакты стенда.

## Что нужно от разработчика

Тестировщику нужны:

- адрес тестового стенда и способ авторизации;
- описание сценариев и тестовых данных;
- способ сброса данных между прогонами;
- стабильные идентификаторы и фича-флаги;
- доступ к логам и трассировке по `request_id`/`trace_id`;
- известные ограничения и порядок сообщения о дефектах.

Если этого нет — e2e превращается в ручной прогон с нестабильными
результатами (flaky). Разработчик обязан дать тестировщику эти точки входа.
