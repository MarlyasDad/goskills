# Skill: Changelog

Переиспользуемое соглашение о ведении `CHANGELOG.md` для всех проектов.

## Формат

`CHANGELOG.md` ведётся в хронологическом порядке (новое сверху). Каждая запись — одна строка: дата, краткое описание изменения и затронутая область. Формат:

```
## v{VERSION} (YYYY-MM-DD)    (опционально, при релизе)

## YYYY-MM-DD
- <область>: <краткое описание изменения> (<автор>)
```

Автор — имя и email из git (`git config user.name` и `git config user.email`).

Пример:

```
## v1.0.1 (2026-08-18)

## 2026-08-17
- api: добавлена пагинация в список заказов (Имя Фамилия <email@example.com>)
- storage: создание каталога БД при подключении (Имя Фамилия <email@example.com>)
```

## Правила

- Обновлять при каждом завершённом изменении (вместе с git commit).
- Описание — краткое (что изменилось и зачем), не дублирует тело коммита.
- Одна строка = одно логическое изменение.
- Каждая строка должна быть под той датой, когда было сделано изменение.
- Дату брать из `date +%Y-%m-%d` или из переменной окружения (сегодняшняя дата).
- Если над датой стоит заголовок версии (`## v{VERSION} (YYYY-MM-DD)`), все изменения ниже до следующей даты/версии относятся к этой версии.
- При релизе (создании git-тега) над верхней датой добавляется строка `## v{VERSION} (YYYY-MM-DD)` — это делает автоматический шаг в CI, агент по запросу пользователя или ручное добавление.
- Если при добавлении изменений над текущей датой стоит заголовок версии, то начать новый блок с той же датой над версией (новые изменения будут относиться к следующей версии).
