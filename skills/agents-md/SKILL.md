# AGENTS.md

`AGENTS.md` — **память проекта**: решения, которые нельзя вывести из
`go.mod`, `Makefile` и кода. Это не копия навыков и не второй свод правил.

- Универсальные правила — в `skills/*`.
- Проектные решения и отклонения — в `AGENTS.md`.
- Секреты — нигде в репозитории.

## Что записывать

| Раздел | Содержание |
|---|---|
| Проект | имя, назначение в одном абзаце |
| Стек | язык, БД, фронтенд, инфраструктура — кратко |
| Модуль и приложения | `module`, `<appname>`, бинарь, короткое имя модуля и причина |
| Команды | реальные цели `Makefile`: `build-<app>`, `run-<app>`, `test`, `test-race`, `lint`, `.bin-deps` |
| Workflow | уточнить → slice → артефакты → проверки → коммит по запросу → итог |
| Конфиг | один `Config` на модуль, env в k8s, локально `configs/.env.local`, секреты |
| Тесты | `testify`/`mockery`, моки генерируются, команды тестов |
| Документация | где спеки, индекс, правило «1–2 релевантных, не все» |
| Скиллы | какие использовать и когда; без дублирования их текста |
| Решения | что сделано иначе, чем в навыке, и почему |
| Границы | что нельзя коммитить, куда не ходить, какие правила безопасности |

## Что не записывать

- Полные тексты правил из навыков — только ссылки:
  «раскладка — `skills/project-structure`».
- Все конвенции кода и тестов: они уже в навыках.
- Секреты, токены, реальные значения конфига.
- То, что видно в `go.mod`/`Makefile`, если достаточно ссылки на команду.
- Историю каждого изменения: только действующие решения и отклонения.

## Иерархия

- Глобальные правила — `~/.config/opencode/AGENTS.md`.
- Проектные — `AGENTS.md` в корне проекта.
- При конфликте побеждает более локальный файл; это явно написано в шапке
  `AGENTS.md`.

## Спеки и навыки

| | Спека | Навык |
|---|---|---|
| Отвечает на вопрос | **что** устроено | **как** делать |
| Содержит | факты, схемы, контракты, статусы | процесс, шаги, чек-лист |
| Где лежит | `docs/specs/` | `skills/*` |
| Как читать | 1–2 релевантных, не все | по триггеру из описания |

- Спеки — источник истины о системе. Перед задачей просканировать индекс
  `docs/specs/README.md`, прочитать 1–2 подходящих целиком.
- Не загружать все спеки сразу: это перегружает контекст.
- Нет подходящей спеки — создать по шаблону проекта.
- Повторяющийся процесс — в навык; факт о системе — в спеку или `AGENTS.md`.

## Workflow

Базовый порядок, если проект не задал свой:

1. Уточнить задачу.
2. Сделать минимальный рабочий slice.
3. Обновить артефакты: `api/`, `migrations/`, `docs/specs/`, `CHANGELOG.md`.
4. Прогнать проверки из `Makefile`: `test`, `test-race`, `lint`, `build-all`.
5. Если нашёл противоречие между навыками — сообщи явно: какой навык что
   требует и где конфликт. Не записывай его в `AGENTS.md` как отклонение
   проекта, пока правило не согласовано. Текст issue — `skills/skill-issue`.
6. Спросить, нужен ли коммит. Без ответа — не коммитить.
7. Вывести итог: какие шаги пройдены и что изменилось.

## Когда обновлять

- при `bootstrap` — создать файл по шаблону;
- при выборе тестового стека, DI, конфига, имени модуля;
- при добавлении адаптера, который меняет `.bin-deps` или структуру;
- при осознанном отклонении от навыка — записать причину, если это не
  конфликт навыков; конфликт сначала согласуется и исправляется в навыках;
- при изменении решения — исправить строку, а не копить противоречия.

Каждый шаг bootstrap и последующих навыков **дописывает** решения, а не
перезаписывает файл.

## Слияние

Если `AGENTS.md` уже есть:

1. Прочитать целиком.
2. Сохранить существующие разделы и формулировки.
3. Добавить недостающие факты и решения.
4. При конфликте — не выбирать молча: зафиксировать оба варианта или
   спросить пользователя.
5. Не дублировать правило, если на него уже есть ссылка на навык.

## Каркас

Готовый шаблон — `references/AGENTS.md`. Скопировать в корень проекта и
заменить `<...>`. Обязательные разделы: проект, модуль и приложения,
команды, конфиг, тесты, правила, решения.

Минимум для нового проекта:

- `module` и приложения;
- команды из `Makefile`;
- ссылки на навыки;
- границы безопасности;
- дата и причина первого отклонения, если оно есть.

## Проверка

- Команды в `AGENTS.md` существуют в `Makefile`.
- `module` совпадает с `go.mod`.
- Нет секретов и реальных `.env`.
- Нет полного дубля текста навыка.
- У каждого отклонения есть причина.
- Файл не противоречит `skills/*`; при противоречии — побеждает явное
  проектное решение, и это видно из записи.

## Границы

- «Где лежит файл» — `skills/project-structure`.
- «Что можно импортировать» — `skills/architecture`.
- «Как читать конфиг» — `skills/config`.
- «Как тестировать» — `skills/testing`.
- «Как оформить навык» — `skills/skill-creator`.
